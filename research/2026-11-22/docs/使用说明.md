# 模块化病毒查杀工具 — 使用说明（v2.0）

作者：军不见　电话：180******66

## 运行

双击 `dist\文件夹病毒查杀工具.exe`（单文件、免安装、无需 Python 环境）。

源码运行：`python FolderVirusKiller.py`（需 Python 3.8+ 且带 tkinter）。
命令行回滚：`python FolderVirusKiller.py --restore "<隔离目录>"`。

插件目录随运行方式变化：
- 源码运行：项目根目录的 `plugins\`
- exe 运行：exe 同级的 `dist\plugins\`（把插件放到这里，重启 exe）

v2.0 起主程序只负责加载与调度模块；**新增功能不需要改主程序**。

## 界面结构

- 顶部「目标位置」：文件类模块使用；非文件类模块自动忽略。
- 中部操作区：每个模块一个分组，按钮由模块自己声明。
- 中部标签页：每个模块一个结果页，由模块自己渲染。
- 底部「日志」与「导出报告」：通用能力，所有模块共享。

### 经典木马查杀（QQKav 功能移植）与拒绝项

- 移植：启动项/Run/RunOnce/RunServices 扫描、QQ尾巴已知特征（KV2004 / WebAuto / Akica / cacom / winsoft / microsoft.exe / EKS）、txtfile 文件关联劫持修复、IFEO 映像劫持修复、hosts 劫持检测、本机共享清点、诊断日志（导出报告）。
- 修复的可回滚性：修复前把被删注册表值原样写入 `legacy_fix_backups\<时间戳>\manifest.json`，点「回滚上次修复」原值恢复；与隔离回滚同一思想。
- 明确拒绝的 QQKav 功能及理由（沿用项目红线）：文件粉碎（不可逆）、网马拦截（注入 IE，现代浏览器无效且高风险）、Winsock 重置（会断网）、开机删毒（绕过所有确认）。相应需求请改用隔离/回滚或 ClamAV 外部引擎。

### 特征库规则包（病毒库更新逻辑）

- 规则包格式：`{"name": "...", "version": 正整数, "source": "可核出处", "rules": [与库内规则同构]}`。
- 版本单调：`version` 必须大于当前库版本且未导入过（禁止降级/重复）；校验失败整包拒绝，不做部分导入。
- 导入前自动把当前库备份到 `signature_db_backups\`（保留最近 10 份），「回滚上次导入」一键还原。
- 规则本身仍遵守：source 可核、T3 只登记禁用、T4 禁止入库。

### U盘/本地磁盘文件查杀流程

1. 点「刷新盘符」→ 下拉选择 U 盘或本地磁盘（含系统盘 C:\）；也可点「选择目录…」只扫指定文件夹。
   - 「允许本地固定磁盘」默认勾选；取消勾选后全部固定磁盘会被拒绝，移动盘不受影响。
   - 目标为系统盘时，点「查杀」或「免疫」会再弹一次系统盘警告确认。
2. 点「扫描」：只读枚举，查看「恶意（红）/ 可疑（黄）/ 正常（灰）」。双击行看依据。
3. 确认无误后点「查杀（隔离+恢复）」：
   - 恶意项移入目标根目录的 `__WORM_QUARANTINE_时间戳\`，保留原相对路径；
   - 被隐藏的原文件解除隐藏+系统属性；
   - **不直接删除任何文件**，可回滚。
4. 「免疫」：在根目录创建只读 `autorun.inf` 文件夹，阻止病毒创建同名自启动文件。若根目录已存在 `autorun.inf`（文件或文件夹），免疫会拒绝执行，请先人工确认原文件性质再处理，工具不代删。
5. 「回滚」：选隔离目录，把隔离项移回原路径。安全规则：目标位置已有同名文件时**不覆盖**（该项跳过留给人工处理）；隔离清单中的可疑路径（穿越/绝对路径）直接拒绝——回滚绝不写出你选择的范围之外。

系统盘护栏：`Windows`、`Program Files`、`ProgramData`、`System Volume Information`、`$Recycle.Bin`、`Recovery`、页面文件等关键路径仍会被扫描并写入报告，但**不隔离、不解除隐藏属性，也不作为「强杀确证」锚点**。这是为避免误搬系统文件导致无法开机的底线；其余路径的查杀逻辑与 U 盘完全一致。报告里通过 `system_protected` 字段和日志「系统保护：…」可核对被保护项。

判定口径不变：

| 判定 | 条件 | 处理 |
|---|---|---|
| 恶意 | 同名隐藏原文件 + `.lnk` 伪装（确证特征）；或 `.lnk` 内容可疑且自身被隐藏 | 隔离 |
| 恶意 | `autorun.inf` 文件 | 隔离 |
| 可疑 | `.lnk` 含可疑串但无确证特征；浅层可疑脚本 | 仅报告 |
| 正常 | 无上述特征 | 保留 |

### 主机诊断（只读）

- 检查 Run/RunOnce、IFEO Debugger、AppInit_DLLs、Winlogon Shell、服务 DLL 路径。
- **只读**：全程只有注册表查询，不修改、不删除、不修复。
- 「高危 / 关注」是待核疑点，不等于「恶意」，不会进入隔离流程。
- 系统正常路径已排除，避免正常 DLL 淹没报告；HKLM 部分项需管理员权限。

### 本地特征库（空库，默认只报告）

**没有预置任何样本、哈希或规则。** 随程序附带的 `signature_db.json` 是空库：源码运行在项目根目录，exe 运行在 `dist\signature_db.json`。程序不会自动联网更新，也不会从网上拉取特征。

七个按钮：

- **初始化空库**：仅在文件不存在时创建，绝不覆盖已有规则。
- **校验规则**：检查每条规则的字段与证据等级，错误规则不会被执行。
- **按库扫描(只读)**：遍历目标文件，只报告命中，不隔离、不删除、不修复。
- **导入规则包(版本化)**：导入带 `name/version/source/rules` 的规则包 JSON，禁止降级与重复导入；导入前自动备份。
- **回滚上次导入**：恢复最近一次备份的规则库。
- **登记误报候选**：把导出报告里的特征库命中登记为误报候选（不会自动改规则）。
- **查看误报记录**：查看已登记的误报候选，供规则复核参考。

规则字段要求：

| 字段 | 要求 |
|---|---|
| `id` | 唯一、非空 |
| `type` | `sha256` / `filename_regex` / `content_regex` |
| `value` | sha256 必须是 64 位十六进制；正则必须可编译 |
| `source` | 可核出处，不能写“未知 / XX / 示例”等占位符 |
| `evidence` | `T1`（原始凭证）或 `T2`（可复算）；`T3` 只能登记、不能启用；`T4` 禁止入库 |
| `first_seen` | `YYYY-MM-DD` |
| `enabled` | 默认 `false`；只有显式 `true` 且校验通过才参与扫描 |

安全边界：

- 命中只表示规则匹配，**不等于病毒确认**；报告字段为 `module_results.signature_db`。
- 本模块**没有隔离动作**，不会调用查杀模块的隔离逻辑。
- 超过 64 MB 的文件会跳过；内容正则只读取前 1 MB，避免卡死。
- 不提供示例规则文件，避免把示例误当真实特征。要加规则，请用你自己取得并可核验的样本。

### ClamAV 外部引擎（公开病毒库，按需扫描）

公开杀毒库这里选的是 **ClamAV**，不是随便抓一份哈希清单：

- Cisco Talos 维护，仓库明确标注 **GPLv2**。
- 官方下载页提供 Windows **x64** MSI / ZIP（1.5.5 版约 214–215 MB）。
- 官方 `clamscan` 是**一次性扫描**，不依赖后台服务；Windows 上按需扫描，不是实时防护。
- 官方特征库 `main.cvd` / `daily.cvd` 由 `freshclam` 更新，通常每天 1–2 次。

本模块的做法：

- **不捆绑** ClamAV 引擎和特征库，不把 200+ MB 的数据塞进 11 MB 单文件 exe，也不因此触发 GPLv2 分发问题。
- 三个按钮：**检查引擎** / **更新ClamAV库** / **ClamAV扫描(只读)**。
- 自动查找 `clamscan.exe` / `freshclam.exe`：依次探测 PATH 与常见安装位置（含 C:/D:/E: 盘根的便携安装，如 `D:\ClamAV`）。
- 扫描只调用 `clamscan --recursive --log=...`，**绝不使用 `--remove` / `--move`**；官方也明确警告误报会导致误删。
- 结果等级为「外部命中 / 信息 / 错误」，**不用「恶意」口径**，不进入隔离流程。
- 扫描日志保存在运行目录下的 `clamav_last_scan.log`。

### 现代威胁检测（只读）

补上主机诊断没覆盖的 6 类持久化/痕迹位置，一个按钮全查：

| 检测项 | 看什么 |
|---|---|
| WMI 事件订阅 | 消费者的 `CommandLineTemplate` 命令行（事件触发时执行，高危持久化点） |
| 计划任务 | `TaskCache\Tasks` 的 Actions 中的可执行路径 |
| 浏览器加载项 | BHO 的 CLSID 指向的 DLL 路径 |
| 脚本文件关联 | `.js/.vbs/.hta/.ps1` 默认打开程序（含 ProgID 间接指向）是否被改为非脚本宿主 |
| 进程路径 | 进程可执行文件路径是否在临时目录或随机命名（不终止进程） |
| 勒索痕迹 | 用户文档目录的赎金笔记文件名 + 同类可疑扩展名批量出现（≥3 个） |

红线：

- **只读**：不写注册表、不创建/删除文件、不终止进程；勒索检测**不创建诱饵文件**。
- **口径**：只用「高危 / 关注 / 信息」，不写「恶意」，不进隔离流程。
- **降噪**：`C:\Windows`、`Program Files` 等系统/官方路径一律跳过；键不存在视为「无此类项」。
- **证据可核**：每行附注册表路径或文件路径 + 原始值，可人工复核。
- **能力边界**：这是疑点登记工具，不是通用杀毒软件。真正确认和清除请交给正规杀毒软件（可配合 ClamAV 模块）。

### 离线取证（WinPE / 离线系统盘，只读）

1. 点「环境识别」：查看是否判定为 WinPE，以及自动定位到的离线系统盘。MiniNT 键可被伪造，单独命中只算「疑似」，需叠加 `SystemDrive=X:` 或 `windir=X:\Windows` 才算确认。
2. 在「目标位置」选择已挂载的离线系统盘根（例如 `D:\`），或用「选择目录」指定，再点「离线取证扫描(只读)」。
3. 模块直读 `<目标>\Windows\System32\config\SYSTEM / SOFTWARE` 与各用户 `NTUSER.DAT` 的 regf 二进制；离线 Hive 没有 `CurrentControlSet`，先读 `Select\Current` 再定位 `ControlSet00x`。同时解析计划任务 XML 与 PE 安全目录，并把注册表里的 `C:\`、`%SystemRoot%`、`%ProgramData%` 翻译成当前挂载盘符。

红线与边界：

- **不挂载 Hive、不提权、不改目标文件**；扫描阶段完全只读，也不会往 `X:\` 写日志或临时文件。
- 只输出「关注 / 信息」待复核线索，不写「恶意」；无内嵌签名 ≠ 恶意（`notepad.exe` 等靠 CatRoot 编录签名）。
- **当前不是 WinPE 原生程序**：Python/PyInstaller 不满足 WinPE 零依赖静态单文件条件，onefile 启动会解压到 `%TEMP%`（PE 下即 X:\）。本模块只完成离线解析与盘符映射逻辑，Rust 静态便携引擎尚未实现。
- 不解析 WMI `OBJECTS.DATA` 结构，不做 `$MFT` 直读、感染型修复、BitLocker 解锁；修复（挂载写 Hive / 删除持久化点）需另行授权且必须先备份。

## 新增功能：加模块即可

### 方式 A：外部插件（推荐，改一个文件就行）

1. 复制 `plugins\_示例模块.py.template` 为 `plugins\我的模块.py`（exe 用户放到 `dist\plugins\我的模块.py`）。
2. 修改 `meta`（`id` 必须唯一）、`actions()`、`run()`，按需实现 `build_view()` / `render()` / `detail()`。
3. 重启程序。主程序会自动发现它，并生成按钮与标签页。

最小结构：

```python
from core.api import Action, ActionResult, ModuleBase

class Module(ModuleBase):
    meta = {"id": "my_module", "name": "我的模块", "version": "1.0", "order": 90}

    def actions(self):
        return [Action("hello", "示例扫描", target_mode="none")]

    def run(self, action_id, ctx, log):
        log("开始。")
        return ActionResult(message="完成。", show_dialog=True, report={"x": 1})
```

契约要点：

- `Action.target_mode`：`required`（必须有目标）/ `optional` / `none`（不需要目标）。
- `Action.confirm`：执行前确认文本；`Action.prompt="directory"`：执行前先选目录（主线程完成，避免线程不安全）。
- `run()` 运行在后台线程，**不要直接操作 tkinter 控件**；结果通过 `ActionResult.data` 交给 `render()` 在主线程渲染。
- `ActionResult.report` 会自动写入导出报告；`data` 仅供界面渲染。
- 需要目标解析时实现 `prepare_context(ctx, raw_target, allow_fixed)`；需要盘符候选时实现 `suggest_targets()`。

### 方式 B：内置模块

把模块文件放进 `modules\`，并在 `core\registry.py` 的 `BUILTIN_MODULES` 里加一行路径。随 exe 一起打包，用户无需自行放文件。

## 导出报告

v2.0 报告同时包含：

- `module_results`：各模块的 action、时间、report（新结构，模块化的通用入口）；
- `root` / `meta` / `items` / `hidden_items`：兼容 v1.x 的 U 盘查杀字段；
- `host_diagnostics_readonly`：兼容 v1.x 的主机诊断字段；
- `caution`：说明主机诊断是只读疑点登记，非病毒确认。

## 边界与风险

- 只针对「文件夹快捷方式病毒」这一已知类型，不是通用杀毒软件。
- 主机诊断只登记疑点、不做修复；合法调试工具也会写 IFEO，不要据此自行删除注册表项。
- 查杀后**必须用杀毒软件对电脑全盘扫描**：病毒常驻主机时，只清 U 盘会复发。
- 高风险操作（查杀 / 回滚 / 免疫）均有二次确认；操作前建议备份重要文件。
- 外部插件属于本机受信任代码：只加载当前运行目录下的 `plugins\*.py`，不会自动联网下载。来路不明的插件不要放进去。
- AMSI 检出是本机杀软 provider 的判定，不是本工具独立结论；provider 未注册或被绕过时可能漏报。

## 对标主流杀软：明确不追的能力（边界声明）

参考火绒 6.0、卡巴斯基 KVRT、Avira、Dr.Web 的公开资料（T3 来源）打磨后，以下能力**明确不做**：
- 通用脱壳 / 虚拟沙盒动态查杀：需要多年引擎积累，Python 只读工具不具备，装作能做只会误导。
- 内核驱动级反 bootkit / Rootkit 扫描：需要内核驱动，超出本工具权限模型。
- 常驻实时防护 / 主动防御：本工具定位是 KVRT/CureIt 式「第二意见按需扫描器」，不驻留后台。
- 文件粉碎：不可逆，违背全部清除必须可回滚的红线。

已吸收的机制：隔离+回滚清单（五家共同底线）、特征命中与启发式分离分级、规则包版本化（KVRT 整包更新思路）、误报反馈记录（Avira 申诉思路）、诊断→注释版修复脚本（KVRT 定制消毒脚本思路）、AMSI provider 评估（火绒 6.0 思路）。

## 隔离、审计与报告（补强说明）

- 隔离清单每项记录 SHA-256、原绝对路径、大小、时间戳、属性与检测依据；回滚前弹窗**显示清单摘要**并逐项校验 SHA-256，目标已存在同名文件不覆盖。中途中断会补偿回滚已搬入项，不留孤儿。
- 回滚只是「准事务」（逐项落盘 + 失败补偿），**不是原子事务**；不要把它当作断电安全的保证。
- 扫描跳过重解析点/Junction/符号链接，限制文件大小与递归深度；报告区分「已扫描 / 跳过 / 无法读取 / 检测 / 未知」，特征命中明确标注「文件哈希 / 特征(文件名) / 特征(内容)」。
- 规则包可带 `sha256`（对 rules 规范化计算，见 `signature_db.rules_sha256`）；不匹配整包拒绝且旧库不变。**没有外部信任根，本工具不提供数字签名验证**，缺 sha256 的旧格式包只给警告。
- 「导出报告」支持 JSON / CSV / 文本三种格式，可选择脱敏（手机号、用户目录、网络主机）；高风险操作（查杀/免疫/回滚/修复等）自动追加写入 `audit.log`。

## 生成报告 ISO（内容刻录）

「通用 → 生成报告ISO」选择存放报告的目录和输出路径，生成 ISO9660 数据镜像：内含所有报告文件与 `SHA256SUMS.TXT;1`，生成后程序会读回校验目录记录。容量上限约 4.3 GiB（4.7GB DVD 实际约 4.38 GiB，留刻录余量），超限拒绝生成。

**边界**：这是数据光盘镜像，不是启动盘。创建可启动 DVD 需要完整 WinPE 或独立启动环境，仅复制应用/报告到 DVD 不会让系统启动；本工具不做引导刻录，也不安装系统级编解码或绕过安全机制。

## 误报申诉（Microsoft Defender / SmartScreen）

本工具打包后的 exe 可能被安全软件误判。按微软官方渠道提交（T1，2026-11-22 核实）：

1. 文件样本提交：https://www.microsoft.com/en-us/wdsi/filesubmission ——选择「Software developer / 软件开发者」身份，产品下拉选择对应的 Microsoft Defender Antivirus 或 Microsoft Defender SmartScreen，附上 exe 与其 SHA-256（发布清单 `dist/SHA256SUMS.txt` 或 GitHub Actions 制品中的同名文件）。
2. 若 Edge/SmartScreen 提示「此网站已被报告为不安全」但确认是误报：在警告页选择「更多信息 → 报告此网站不包含威胁」，按反馈页指引提交。
3. 提交前自查：exe 来自本项目 GitHub Actions 构建产物且 SHA-256 与发布清单一致；不要提交来源不明或被篡改的二进制。
