# 实证结论清单 · 2026-11-22

只记录**实测得出**的结论，并标注可复现方式。凡未验证的，写在最后一节，不进正文。
标签口径：T1=原始凭证，T2=基于 T1 的可脚本复现计算，T4=推演（不进事实层）。

## 一、被实测推翻的"常识"

| # | 流传的说法 | 实测结论 | 证据 |
|---|---|---|---|
| 1 | `.cat` 编录里存的是**整文件**哈希 | 存的是文件的 **Authenticode 摘要**。`notepad.exe` 的整文件 SHA-1/SHA-256 在 1453 个编录里命中 **0 次**，Authenticode 摘要命中 1 次 | T2：按两种口径各扫一遍全量 CatRoot |
| 2 | PKCS#7 的 `messageDigest` 对**完整 DER** 计算 | 对 `[0]` 内元素的 **value 八位组**计算（不含自身 tag/len）。PE 内嵌签名与 `.cat` 同一口径 | T2：按完整 DER 算，1442 个合法编录全报"摘要不一致"；改口径后全通过 |
| 3 | 证书过期即不可信 | 必须结合 **RFC3161 时间戳**：验令牌自身签名 + 校验 imprint 绑定本次签名 + 按 `genTime` 复验证书有效期。本机微软叶证书 2026-06-17 到期、中间证书 2026-10-19 到期，靠令牌（genTime 2026-03-01）才算有效 | T2：不加时间戳则 1442 个编录全判失效 |
| 4 | 现代 `cryptography` 无运行时依赖 | 仍依赖 **cffi**（`_cffi_backend`）。绿包用 `--no-deps` 装 wheel 后 `AESGCM` 直接 `ModuleNotFoundError` | T1：绿包内 `from cryptography...aead import AESGCM` 报错；补 cffi 2.1.1 + pycparser 3.12 后通过 |
| 5 | 把 exe 拷到 C 盘就不会往内存盘解压 | onefile 的解压位置由运行时 `TEMP`/`TMP` 决定（或构建时 `--runtime-tmpdir`），**与 exe 所在盘无关**；且解压发生在 Python 启动**之前**，代码里改 `TEMP` 已晚 | T1：PyInstaller 官方文档 + 实测启动器设 `TMPDIR/TEMP/TMP` 才生效 |
| 6 | 设 `TEMP`/`TMP` 就够 | Windows 上 `tempfile` 候选顺序是 **`TMPDIR` → `TEMP` → `TMP`**，继承的 `TMPDIR` 会覆盖 | T2：只设后两者时 `gettempdir()` 仍返回旧目录 |
| 7 | 可用"字符串集合相等"判断 exe 是否由当前源码构建 | 不可行：CPython 把 `"a %s b" % (x,)` 编译成 `BUILD_STRING` 的**分段常量**（`'a '`、`' b'`） | T1：`dis` 输出 `LOAD_CONST '回滚失败 '` + `FORMAT_VALUE` |

## 二、判定层的量化结果（T2，可复跑）

| 项 | 数值 | 口径 |
|---|---|---|
| System32 抽样验签 | 80 个文件 → 38 个有内嵌签名**全部摘要一致**（sha256 36 / sha1 2），42 个无内嵌签名，0 不一致 | 与微软签名机写入的摘要逐字节比对 |
| 编录索引 | 1453 个 `.cat` → 验签通过 **1442**、拒绝 5、解析失败 **0**、**96,135** 条摘要、**3.78 s** | 全量 `C:\Windows\System32\CatRoot` |
| 被拒的 5 个 | 2014 年 OEM 驱动编录：证书过期且**无时间戳**，无法证明当时有效 → 拒绝（其文件降为灰，不是判恶意） | 拒绝原因逐条核对 |
| `notepad.exe` | SHA-1 `546f6d80…` 与 SHA-256 `55633dc3…` **双命中**同一编录；随机 32 字节摘要不命中 | 双摘要正反测 |
| 双签名普查 | `System32`+`SysWOW64` **7191 个文件 → 双签名 0 个** | 结论：该分支无真实样本，只有合成用例 |
| 计划任务解析 | 本机 228 条任务、**0 解析错误** | 只读解析 `C:\Windows\System32\Tasks` |

## 三、端到端行为（T2）

| 场景 | 结果 |
|---|---|

## 五、事故复盘：源码已修、exe 仍是旧的

- 现象：点「扫描」弹"安全拦截：目标是系统盘 C:\，拒绝处理"。
- 根因：源码 `7be5585`（13:27:59）已放行固定盘；`dist` 里的 exe 构建于 **11:37:42**，早 1h50m。
- 判据（内容级，不看时间戳）：旧 exe 内嵌 `modules.folder_virus` 仍含"拒绝处理"；新 exe 两条旧话术都不在，且含"允许本地固定磁盘 / 系统关键路径 / 仅报告"。
- 机制化：`tools/check_exe_freshness.py` —— 旧话术必须消失、放行文案必须存在、源码比 exe 新即判过期。双向验证：新 exe `PASS`，旧 exe `FAIL`（三条原因）。
- 教训：`dist/` 被 `.gitignore` 排除，二进制不在仓库里，"改了源码忘重打包"不会有任何提示——必须靠门禁，不靠记性。

## 六、未验证（不得当成已完成）

1. 真实 **WinPE** 环境：缺 DLL、只读 `X:`、scratch 空间、BitLocker 锁盘，全无实测证据。
2. `yara-x` 未安装；当前真正生效的规则只有内置 EICAR 特征，适配层存在 ≠ 有完整查杀能力。
3. 双签名路径无真实样本，"优先校验 SHA-256"只在合成用例上验证。
4. 绿包清单与 exe 均**未签名**：能改文件的人也能改清单，防投毒需 Ed25519 签名 + 公钥硬编码。
5. 吊销仅支持指纹清单，**不是完整 CRL/OCSP**；被盗用的合法证书在没有名单时会放行。
6. Rust 静态引擎、`$MFT` 直读、感染型修复、MBR/EFI 校验：未做。
